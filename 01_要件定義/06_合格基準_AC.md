## 📐 概要

本章は F001〜F051（**欠番除き 38 機能**）に対し、**Given-When-Then（BDD 風）** 形式で合格基準を定義する（As-Built v0.49.1 実績ベース、2026-09-15 同期）。状態列の ✅ は実装 + 手動 UAT + **vitest 1362 件 PASS** で検証済みを示す。**F029 / F034 / F035 / F036 / F037 は欠番**。F006 は **11 タブ**化、F011 は **5 プロバイダ・Zhipu 純 TS 化** を反映。

## 🎯 F001〜F031（既存 AC）

> F001〜F031（F029 欠番）の 34 件 AC は v2.1.0 で定義済み。本ファイルでは v0.49.1 で追加された AC-F032〜AC-F051 を主として記載。

## 🎯 F032 選択ポップアップ位置設定

```
Given  selection.popupPosition = 'top-right'（既定） / 'bottom'
When   テキスト選択でフローティングポップアップが表示される
Then   - 'top-right': 選択テキストの右上端を基準に表示
And    - 'bottom': 選択テキストの下端を基準に表示（v0.38.0 まで既定）
And    - ビューポート端でのクランプ/反転は両モード共通
And    - 設定タブ「選択」ドロップダウンで切替可能（i18n 3 ロケール）
```

## 🎯 F033 LLM 原稿整形の堅牢化

```
Given  tts.llmRewriteConcurrency = 1〜8（既定 2）
When   入力テキストから AI 整形（claude -p）を経由して TTS 再生する
Then   - LLM 原稿は全プロファイルで「です・ます調」に統一される
And    - 並列生成数 1〜8 件の範囲で設定可能（既定 2）
And    - ストリーミング読上げで原稿生成中の Notice「📝 原稿生成中 n/m…」が残らない（v0.37.2 で根治）
And    - file-open / mute / 新規 Add-to-TTS での中断が世代ガードで安全
```

## 🎯 F038 MD 読み上げクリーン化

```
Given  MD ファイル本文に `<style>` または `<script>` タグが含まれる
When   「Add to TTS」で読み上げを開始
Then   - `<style>` / `<script>` タグとその中身が読み上げ対象から除去される
And    - CSS / JS 注入コードが読み上げ音声に乗らない
```

## 🎯 F039/F040 🤖 Think モード選択機能

```
Given  tts.thinkMode = 'enabled' / 'disabled' / 'auto'
When   TTS 読上げ経路（selection / autoRead / message / inputAi）から LLM を直接呼び出す
Then   - Claude (Phase 1, F039): thinking 表示の有無を切替
And    - DeepSeek / Zhipu / MiniMax / Kimi (Phase 2, F040): 5 プロバイダ対応
And    - LlmClient 抽象化 + dispatch.ts で統一経路
And    - httpGet ベースのため Python / JWT 依存なし
```

## 🎯 F041 OpenVPN 接続機能

```
Given  network.openvpn.configPath に有効な .ovpn ファイル、auth-user-pass の username/password が設定済み
When   プラグインが onload または LLM dispatch 前の ensureVpnConnected() を実行
Then   - openvpn CLI が spawn され、stderr + stdout の両方を監視
And    - 「Initialization Sequence Completed」検出で connected 状態に遷移
And    - state 4 値（disconnected / connecting / connected / error）+ リアルタイムログ
And    - Obsidian クラッシュ時の孤児プロセスは reapOrphanOpenVpn() で PID ファイル + auth マーカーから自動回収
And    - プラグイン無効化時に VPN も自動切断（ゾンビプロセス防止）
```

## 🎯 F042 🌐 ネットワークタブ新設

```
Given  プラグインが有効
When   設定 → Claudian Bridge を開く
Then   - 「🌐 ネットワーク」タブが一般とテキスト挿入の間に表示される
And    - プロキシ設定（v0.38.0 で一般タブから移動）+ OpenVPN 接続セクションが同居
And    - i18n 20 キー追加（ja / en / zh-CN）
```

## 🎯 F043 Claudian 画面 OpenVPN トグル

```
Given  network.openvpn.configPath 設定済み、Claudian 画面が開いている
When   YOLO トグル横の VPN トグルをクリック
Then   - ワンショット方式で start / stop を即実行（接続中は disabled）
And    - 状態バッジ 4 値（🔴 切断 / 🟡 接続中 pulse アニメ / 🟢 接続済 / 🔴 エラー）がリアルタイム反映
And    - 設定未完了時はクリックで Notice + 設定タブ（ネットワーク）へ自動遷移
And    - 複数 Claudian タブに MutationObserver で自動追随
And    - 「OpenVPN を使用」を OFF にするとトグルが消える（disabled → hidden）
```

## 🎯 F044 Server Override（DDNS 上書き）

```
Given  network.openvpn.serverOverride に DDNS ドメイン（例: vpn.example.com）
When   OpenVPN 接続を開始
Then   - openvpn CLI に `--remote vpn.example.com 1194`（または `:port`）が追加される
And    - .ovpn の remote 行は上書きされ、DNS 解決は openvpn 側で行う（プラグインは DNS 解決なし）
And    - 空欄時は .ovpn の remote を使用（後方互換）
```

## 🎯 F045 残骸経路の検知

```
Given  OpenVPN ログに `[DHCP-serv: 10.8.0.13]` が出力され、route print に複数の経路が存在
When   接続完了の 2.5 秒後に F045 の経路検証が走る
Then   - 正しいゲートウェイ（10.8.0.13）の経路が無ければ「経路未確立 + 残骸」警告
And    - 正しい経路はあるが残骸（10.8.0.5 / 10.8.0.9 等）が混在すれば「残骸経路残存」警告
And    - 正しい経路のみなら警告なし
And    - `On-link` 行はゲートウェイとして扱わない（誤判定防止）
```

## 🎯 F046 残骸経路の 1 クリック削除

```
Given  F045 で「残骸経路残存」が警告されている
When   設定 → 🌐ネットワーク → 🧹 Remove stale routes ボタンを押下
Then   - 管理者判定（isRunningAsAdmin）が実行される
And    - 管理者起動時のみ VPN ホワイトリスト化された経路のみを route delete
And    - ローカル LAN の経路は絶対に触らない
And    - 削除結果（成功件数）が Notice で通知される
```

## 🎯 F047 切断時の残骸経路自動削除

```
Given  OpenVPN 接続中
When   stop() が呼ばれる（手動切断 or プラグイン無効化）
Then   - setTimeout(3000) で cleanupAfterDisconnect() をスケジュール
And    - バックグラウンドで stale 経路を検出（管理者起動時のみ自動削除）
And    - 手動 🧹 ボタンも継続有効
```

## 🎯 F048 Zhipu 残量取得の純 TypeScript 化

```
Given  Zhipu API キーが data.json に保存されている
When   「接続テスト」または quotaRefreshSec ごとの自動取得が走る
Then   - https://open.bigmodel.cn/api/monitor/usage/quota/limit へ生 API キーで Bearer 認証の GET
And    - JWT / SDK 不要（実機検証済み）
And    - unit 3（5h）と unit 6（週）の usage 情報を取得
And    - window='5h'（既定）で unit 3、無ければ unit 6 にフォールバック
And    - window='week' で unit 6、無ければ unit 3 にフォールバック
And    - 401/403 → expired 扱い、500/parse エラー → error 扱い
And    - _query_zhipu_quota.py / zai-sdk への参照がゼロ（Python 依存ゼロ化）
```

## 🎯 F049 Outputs フォルダミラリング

```
Given  general.outputsMirrorEnabled = true、general.outputsMirrorPath が Documents/ObsidainOutputs
When   プラグインが onload で起動
Then   - Documents/ObsidainOutputs を Vault/Outputs として NTFS ジャンクションで表示
And    - Vault 側 Outputs 実フォルダ既存時は有効化不可（実フォルダ優先・Notice で理由表示）
And    - general.hideDotFolders = true（既定 ON）で `.` 始まりのフォルダを非表示
And    - 「📂 開く」ボタンで outputsMirrorPath を Explorer で開ける
And    - 📜 改定履歴タブで CHANGELOG.md を SSOT として全バージョン表示（アコーディオン）
And    - npm run check:changelog でリリース時に CHANGELOG 更新を強制
```

## 🎯 F050 💬 チャット読上げハイライト

```
Given  tts.chatReadHighlight.enabled = true（既定 ON）、Claudian 画面が開いている
When   タスク完了報告の 📢 ブロック生成 → 自動読み上げが発火
Then   - 最後の .claudian-message-assistant に `cb-chat-read-active` クラスと背景色インライン付与
And    - scrollIntoView で画面中央へスクロール
And    - 世代トークン（latestToken）で割り込み時の旧 speak finally が新ハイライトを誤解除しない
And    - 読上げ完了 / ✋手動停止 / 次の質問で割り込みのいずれでも確実に解除される
And    - 設定 OFF 時: ハイライトが付かない
And    - v0.49.1 ホットフィックス: Forced reflow ピーク 114ms → 53ms に削減
```

## 🎯 F051 📄 MD 画面 Add to TTS ボタン

```
Given  MD ファイルが Preview モードで開かれている
When   ビューヘッダ右上 ✏️ の左に 🔊 ボタンが表示される
Then   - MarkdownView.addAction('volume-2', ...) で描画（DOM ハック不要）
And    - クリックで右クリックメニューと同一経路 addMdToTts(...) が呼ばれ、読み上げ開始
And    - 既存の F028（MD ハイライト）と F050（チャットハイライト）が自動的に連動
And    - layout-change で再描画されても [data-cb-add-tts] マーカーで重複追加されない
```

## 1. 背景・目的

v0.46.0（F-046）で残骸経路の **検知** と **1 クリック削除** を実装したが、毎回ユーザーが「🧹 削除」ボタンを押す必要がある。実運用では「切断 → 再接続」を繰り返すため、**stale 経路の自動削除** が望まれる。

| # | 現状課題 |
|:-:|----------|
| A | 切断 → 再接続 のたびに 🧹 ボタン押下が必要 |
| B | v0.46.0 の仕様（VPN 使用時は Obsidian を管理者起動）は維持しつつ、運用負荷を減らしたい |
| C | ユーザーが意識しなくてもクリーンな状態が保たれるのが理想 |

本設計で次を実現する：

| # | 項目 |
|:-:|------|
| A | OpenVPN 停止ボタン押下後、3 秒待機してからバックグラウンドで stale 経路をチェック |
| B | 管理者起動中なら自動で削除（ユーザー操作不要） |
| C | 非管理者起動や失敗時は警告のみ（安全性重視） |

---

## 2. 要件（決定済み）

| # | 要件 |
|:-:|------|
| A | 「🔌 切断」ボタン押下 → openvpn プロセス停止成功 → 3 秒待機 → バックグラウンドで stale 検出 |
| B | 管理者起動中なら、stale 経路を自動削除（v0.46.0 と同じ whitelist） |
| C | 管理者起動でない場合は **警告も通知もしない**（バックグラウンドで静かに諦める） |
| D | 削除件数が 1 件以上の時のみ Notice 表示 |
| E | 失敗した GW があれば Notice に追記 |

### 非要件

| # | 項目 |
|:-:|------|
| X | OpenVPN の接続中・接続時の stale 削除 |
| Y | ユーザーの「🧹 ボタン押下」の廃止（v0.46.0 の UI は引き続き有効） |
| Z | 切断以外のタイミング（プラグイン起動時等）での削除 |

## 3. 設計

### 3.1 全体フロー

```
[ユーザが「🔌 切断」ボタン押下]
        ↓
[OpenVpnController.stop()]
        ↓
[openvpn.exe 停止成功を待つ]
        ↓
[setTimeout(cleanupAfterDisconnect, 3000)]
        ↓ (3 秒後)
[cleanupAfterDisconnect()]
        ↓
[1. isRunningAsAdmin() 判定]
    - false → 静かに return（通知なし）
        ↓ true
[2. getVpnRoutes() で VPN ルート取得]
        ↓
[3. findStaleRoutes(routes, null)]
    expectedGateway = null → 全 VPN ルートを stale 扱い
        ↓
[4. 各 stale ルートを route delete]
        ↓
[5. 削除件数 + 失敗 GW を Notice で通知]
```

### 3.2 既存メソッドの活用

v0.46.0 の `removeStaleRoutes()` をそのまま活用する：

```typescript
// v0.46.0 で実装済み
public async removeStaleRoutes(): Promise<RemoveStaleResult>
```

ただし、内部の `this.expectedGateway` を一時的に `null` にして呼ぶ必要がある。切断後のセッション情報はもう利用できないため。

**実装方針**: `removeStaleRoutes()` を直接呼ばず、薄いラッパー関数 `cleanupAfterDisconnect()` を新設する。

```typescript
/** F-047: 切断後のバックグラウンド stale 削除 */
private async cleanupAfterDisconnect(): Promise<void> {
  if (!this.isRunningAsAdmin()) return; // 非管理者は静かに諦める
  const routes = this.getVpnRoutes();
  if (routes === null) return;
  // expectedGateway = null にして全 VPN ルートを stale 扱い
  const stale = this.findStaleRoutes(routes, null);
  if (stale.length === 0) return; // 何もなければ無音

  let removed = 0;
  const failed: string[] = [];
  for (const r of stale) {
    try {
      execSync(`route delete ${r.dest} mask ${r.mask} ${r.gateway}`, {
        stdio: ['ignore', 'pipe', 'pipe'],
        timeout: 3000,
      });
      removed++;
    } catch {
      failed.push(`${r.dest}/${r.mask} via ${r.gateway}`);
    }
  }

  if (removed > 0 || failed.length > 0) {
    new Notice(s.networkOpenVpnAutoCleaned
      .replace('{count}', String(removed))
      .replace('{failed}', failed.length > 0 ? `（失敗: ${failed.join(', ')}）` : '')
    );
  }
}
```

### 3.3 タイミング

| 段階 | 待機時間 | 理由 |
|------|---------|------|
| openvpn.exe 停止 → cleanup 開始 | 3 秒 | OpenVPN がルートを消す時間を確保。短すぎると正常なルートを消してしまうリスク |
| route delete タイムアウト | 3 秒/コマンド | v0.46.0 と同じ |
| 全体タイムアウト | 10 秒 | 古いタイマーが残らないよう clearTimeout 可能に |

### 3.4 UI 統合

v0.46.0 の UI は **そのまま残す**（手動削除ボタンも有効）。F-047 は **追加機能** であり、既存 UI を変更しない。

### 3.5 エラー処理

| 失敗ケース | 挙動 |
|-----------|------|
| 非管理者起動 | 静かに return（通知なし） |
| `getVpnRoutes()` が null | 静かに return（通知なし） |
| stale が 0 件 | 静かに return（通知なし） |
| 一部失敗 | `removed` + `failed` を Notice 表示 |
| 全失敗 | `removed: 0, failed: N` を Notice 表示 |

## 7. テスト方針

| テストケース | 検証内容 |
|-------------|----------|
| `cleanupAfterDisconnect()` 正常系 | admin + stale 2 件 → 2 件削除 → Notice 表示 |
| `cleanupAfterDisconnect()` 非管理者 | admin probe 失敗 → 静かに return（Notice なし） |
| `cleanupAfterDisconnect()` stale 0 件 | stale なし → 静かに return（Notice なし） |
| `stop()` 後のタイマー起動 | `setTimeout` が cleanup を 3 秒後に呼ぶことを確認（fake timers） |

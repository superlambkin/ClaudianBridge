## 🧭 機能改良時の運用ルール（2026-09-13 新設）

| # | 手順 | 内容 |
|:--:|------|------|
| 1 | 設計書作成 | テンプレート [[80_POC_Projects/POC_000_templates-v3.5/02_設計文書/30_機能改良設計テンプレート\|30_機能改良設計テンプレート]] を使い **`NN_機能名設計.md`**（次の空き番）として作成。**date 名（2026-XX-XX-…-design.md）は禁止** |
| 2 | 改良の場合 | 該当する統合設計書（[[23_TTS読み上げ統合設計]] / [[24_トークン速度表示統合設計]] / [[25_チャットUI統合設計]] / [[26_入出力補助統合設計]]）または基幹文書（00〜08）の **「🕘 改定履歴」に行を追加** + 現行仕様の章を最新化 |
| 3 | 基幹文書 | 00/01/04/05/08 のアーキテクチャ・クラス・データモデル・API・セキュリティも変更があれば同時更新 |
| 4 | F-番号 | [[F-number_master]] に起票しバージョンを紐付け |
| 5 | リリース | CHANGELOG.md にエントリ追加（**`npm run check:changelog` ゲート必須**）・リリース後 F-number_master / バージョン履歴 / リリースノートを更新 |
| 6 | 原本 | superpowers 由来のドラフトは作成時に `NN_` 改名するか、統合時に `_superpowers原本/` へ退避（原本放置禁止） |

## 1. 背景・目的

v0.45.0 で「残骸経路（死んだセッション）の検知」を実装したが、検知のみで **削除手段がない**。ユーザーは警告を見るたびに PC を再起動するか、手動で `route delete` を実行する必要があり、運用上のストレスが大きい。

| # | 現状課題 |
|:-:|----------|
| A | 残骸経路を検知できても、消す手段が提供されていない |
| B | OpenVPN の切断→再接続だけでは stale 経路は **消えない**（実測） |
| C | `route delete` には管理者権限が必要だが、ClaudianBridge は普段非管理者で動く |

F-045（管理者権限分離による自動削除）は **DCO モードで機能せず** ロールバック済み。本設計は **「VPN 使用時は Obsidian を管理者起動する」運用** を前提に、その前提が満たされている時のみ 1 クリックで残骸経路を削除する。

---

## 2. 要件（決定済み）

| # | 要件 |
|:-:|------|
| A | 残骸経路検知時のみ、`🧹 残骸経路を削除` ボタンをネットワークタブに表示する |
| B | ボタン押下時、Obsidian が **管理者起動** されていることを判定する |
| C | 管理者起動中であれば、stale ゲートウェイに紐づく全 VPN ルートを `route delete` で削除する |
| D | 管理者起動でない場合は、その旨を Notice で知らせる（ボタン非活性 or 警告） |
| E | 削除対象は VPN 関連ルートのみ（0.0.0.0/1、128.0.0.0/1、10.8.0.0/8）。ローカル LAN は **絶対に触らない** |
| F | 削除完了時に件数を Notice で通知、失敗時はその旨を表示 |

### 非要件

| # | 項目 |
|:-:|------|
| X | 平時の非管理者起動から自動削除すること（F-045 ロールバックの結論を尊重） |
| Y | OpenVPN プロセスを介さず自前でルートを操作すること |
| Z | 10.8.0.0/8 以外の独自 VPN レンジのサポート（汎用のホワイトリストで吸収） |

## 3. 設計

### 3.1 全体アーキテクチャ

```
[ユーザ] → [ネットワークタブ]
              ↓ 残骸経路警告表示中
              ↓
[🧹 ボタン押下]
              ↓
[管理者判定] ─→ 非管理者 → Notice「Obsidian を管理者として再起動してください」
              ↓
              管理者
              ↓
[stale 抽出] getVpnRouteGateways() で VPN 関連 GW 全取得
              ↓ expectedGateway と比較
              ↓ stale GW リスト
[stale 削除] route delete <dest> mask <mask> <stale_gw> × N 件
              ↓
[結果通知] Notice「✅ N 件の残骸経路を削除しました」or 失敗メッセージ
              ↓
[再検証] getVpnRouteGateways() で残骸ゼロを確認 → 警告解除
```

### 3.2 セキュリティ境界

ルート削除対象は **OpenVPN が push する VPN 関連ルートのみ** に厳格に限定：

| 対象 | 判定ルール |
|------|------------|
| `0.0.0.0` / `128.0.0.0` (mask `128.0.0.0`) | OpenVPN の redirect-gateway |
| `10.8.0.0` 〜 `10.8.255.255` | OpenVPN の典型的なトンネレンジ |
| `192.168.0.0` 〜 `192.168.255.255` 等 | **触らない**（ローカル LAN） |
| `default` 等の DNS 経路 | **触らない** |
| ゲートウェイが `On-link` の行 | スキップ（VPN ルートではない） |

判定は v0.45.0 で実装した `getVpnRouteGateways()` のフィルタをそのまま流用する。

### 3.3 管理者判定

`route delete 0.0.0.0 mask 128.0.0.0 10.255.255.255`（失敗確実なコマンド）を **ボタン押下直前に** 実行し、`execSync` の戻り値／例外で判定する。

- 成功（exit 0） → 管理者として実行された
- 失敗（exit 1） → 管理者でない or route がない

> ⚠️ **注意**: 失敗確実なコマンドで実環境に副作用が出ないよう、`10.255.255.255` という存在しないゲートウェイを指定。route 削除は「ルートが存在しない」場合は exit 1 になるが、管理者でない場合は exit 5 (ERROR_ACCESS_DENIED) になる。両者を区別するため、**stderr テキスト** も確認する：
> - `ERROR_ACCESS_DENIED` を含む → 非管理者
> - `The route deletion failed` を含む → 管理者（ルートがない）

実装は `isRunningAsAdmin(): boolean` 純粋関数として切り出し、テスト時は `execSync` を mock 化する。

### 3.4 stale 経路の抽出

`getVpnRouteGateways()` は v0.45.0 で実装済み。F-046 ではこれを拡張し、**dest/mask/gateway の3-tuple** を返す `getVpnRoutes()` を新設する。

```typescript
type VpnRoute = { dest: string; mask: string; gateway: string };
function getVpnRoutes(): VpnRoute[] | null
function findStaleRoutes(routes: VpnRoute[], expectedGateway: string | null): VpnRoute[]
```

`expectedGateway` が null（ログ未取得）の場合は **全 VPN ルートを stale 扱い** とする（安全側に倒す）。

### 3.5 削除実行

```typescript
function removeStaleRoutes(routes: VpnRoute[]): { removed: number; failed: string[] }
```

各ルートに対し `execSync('route delete <dest> mask <mask> <gateway>', ...)` を実行。例外を catch してエラー詳細を返す。

タイムアウト：1 コマンド 3 秒、合計 10 秒。上限超過は打ち切り。

### 3.6 UI 統合

`SettingTabNetwork.ts` の `renderOpenVpnStatus()` に：

```typescript
const removeBtn = containerEl.createEl('button', { text: s.networkOpenVpnRemoveStale });
removeBtn.style.display = warning ? '' : 'none';
removeBtn.addEventListener('click', async () => {
  const result = await controller.removeStaleRoutes();
  new Notice(s.networkOpenVpnRemoved.replace('{count}', String(result.removed)));
  // 失敗時は controller.warning が更新される
});
```

ボタン表示条件：
- `controller.getWarning()` が非 null（v0.45.0 の検知ロジック）
- 警告テキストに「残骸経路」が含まれる（経路未確立の警告とは区別）

### 3.7 エラー処理

| 失敗ケース | 挙動 |
|-----------|------|
| 非管理者で実行 | `networkOpenVpnNeedAdmin` Notice 表示 |
| `route delete` 失敗 | 失敗した GW をリストで通知 |
| `getVpnRoutes()` が null（route print 失敗） | `networkOpenVpnRemoveFailed` Notice |
| 削除後に stale が残存 | `controller.warning` を再評価（自動で残骸警告が再発） |

## 7. テスト方針

| テストケース | 検証内容 |
|-------------|----------|
| `getVpnRoutes()` 正常系 | route print 出力から dest/mask/gateway 抽出 |
| `getVpnRoutes()` 異常系 | execSync 失敗時 null |
| `findStaleRoutes()` 正常系 | expectedGateway と異なる GW のみ返す |
| `findStaleRoutes()` null 経路 | expectedGateway=null → 全 VPN ルートを stale |
| `removeStaleRoutes()` 正常系 | mock execSync で全削除成功 |
| `removeStaleRoutes()` 部分失敗 | mock execSync で 1 件失敗 → failed リスト |
| `isRunningAsAdmin()` 正常 | stderr `ERROR_ACCESS_DENIED` → false |
| `isRunningAsAdmin()` 拒否 | exit 5 + stderr 拒否 → false |
| `isRunningAsAdmin()` 許可 | exit 0 or stderr 別文言 → true |

## 🎓 主要な学び

> 詳細は [[80_POC_Projects/POC_017_ClaudianBridge/06_振り返り/01_経験教訓|経験教訓]] を参照

1. **「Iron Law of 3 strikes」**: 同じ問題で 3 回修正したら、アーキテクチャ自体を見直す（v0.7.0 anime-tts → v0.8.0 Plachta 置換の根拠）
2. **spawn 依存の罠**: Obsidian/Electron renderer の `spawn` 環境は pipe buffer / stdin / stderr の三重苦 → クラウド API 化が根本解決
3. **「manifest.json 一元化」**: バージョン表示のハードコードは SSOT 違反 → v0.8.0 で `Plugin.manifest.version` 参照に統一
4. **「マイグレーション 1 度だけフラグ」**: `noticeShown` フラグで冪等性担保（chroma / minimax / damarcreative で 3 度同じパターン）
5. **「0.x 系の爆速リリース」**: 1.0.0 未満は仕様変更自由を活かし、機能追加ごとに minor bump でリリース
6. **🔴 「パフォーマンス障害は 🔴 リスクとして即対応」**: v0.49.0 リリース → v0.49.1 hotfix（**1 日以内**）で Forced reflow 嵐を解消
7. **「リアルタイム観察 → 即修正」**: v0.49.1 で `[Violation] Forced reflow` を DevTools で観察 → `requestAnimationFrame` 化で根本対策
8. **「依存ゼロ化は運用安定の銀の弾丸」**: Zhipu Python 依存 → 純 TS 化（v0.48.0）で環境不備の障害を根絶

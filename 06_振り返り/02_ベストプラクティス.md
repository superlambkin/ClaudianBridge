## ✅ DO 推奨プラクティス

### 設計フェーズ

| # | DO | 理由 |
|---|-----|------|
| 1 | 外部依存は**クラウド API 化**を検討（ローカル spawn より堅牢） | Electron renderer の spawn は pipe buffer 等の罠 |
| 2 | 複数経路の処理は**共通エントリポイント**に集約（`speakText`） | 空テキスト・エラー処理の一元化で回帰を防止 |
| 3 | **設定スキーマに normalize/validate** を実装 | 旧データ・欠落フィールドの安全な補完 |
| 4 | **SSOT を決める**（manifest.json / voice-config.json） | 二重管理による不整合を排除 |
| 5 | マイグレーションは**冪等 + 1 度だけフラグ** | 再起動・再実行による重複を防止 |

### 実装フェーズ

| # | DO | 理由 |
|---|-----|------|
| 1 | **TDD で実装**（バグ修正には回帰テストを追加） | 592 passed の回帰網を維持 |
| 2 | **診断ログ**（`[cb-*]`）を主要フローに仕込む | 実機での原因特定を高速化 |
| 3 | **onunload で cleanup**（CSS 除去・quota 解除） | メモリリーク・二重適用を防止 |
| 4 | 外部 API は**タイムアウト + フォールバック**を用意 | Plachta / claude -p の失敗時も元文で継続 |
| 5 | デプロイは**共有スクリプト + マーカー検証** | stale main.js の誤デプロイを防止 |

### 運用フェーズ

| # | DO | 理由 |
|---|-----|------|
| 1 | バージョンアップ前に `npm run typecheck` + `npm test` | 回帰を事前検出 |
| 2 | Quota 残量を週次確認 | API 切れによる機能停止を防止 |
| 3 | 旧プラグインは `_disabled__` のまま維持 | 再有効化による二重注入を防止 |

---

## ❌ DON'T 非推奨・禁止

| # | DON'T | 代替 |
|---|------|------|
| 1 | **ハードコードのバージョン文字列** | `Plugin.manifest.version` を参照 |
| 2 | **ローカル Python spawn への過度な依存** | クラウド API / HTTP 直接呼び出し |
| 3 | **複数の読み上げ経路を個別実装** | 共通 `speakText` に統合 |
| 4 | **自動読み上げで途中ターンを読む** | 最終回答ゲートで検出 |
| 5 | **旧プラグインの再有効化** | `_disabled__` 維持 |
| 6 | **worktree 間でバージョンを個別に bump** | main 統合後に一元 bump（v0.20.0 の不整合を教訓に） |
